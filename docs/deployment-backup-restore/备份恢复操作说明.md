# IMS 部署机备份与恢复

在 Windows 部署电脑上操作。准备已迁移的项目代码、PowerShell 7、Node.js 和 PostgreSQL 工具。解压后从包所在目录运行命令。操作脚本调用项目自带的 scripts/platform/maintenance.cjs。

## 1. 准备配置

复制部署机实际运行配置为 maintenance.private.json，参照 maintenance.template.json 补齐或替换下表字段，保留实际运行配置中的其他字段。使用 UTF-8 无 BOM 保存。密码只填写到受限目录中的私有配置。

| 字段 | 填写要求 |
|---|---|
| IMS_PLATFORM_DB_URL、IMS_PLATFORM_DB_USER、IMS_PLATFORM_DB_PASSWORD | 源平台的实际 PostgreSQL 连接、账号和密码。改示例的端口和库名。脚本只接受本机连接，库名须以 ims_platform_dev、ims_platform_test 或 ims_platform_trial 开头。若实际连接不符合，先停在检查阶段。 |
| IMS_PLATFORM_PORT | 源平台应用实际监听端口，用于判断应用是否停机。 |
| IMS_BACKUP_POSTGRES_BIN | 改成实际 PostgreSQL bin 目录，包含 psql、pg_dump、pg_restore、createdb。初始化隔离实例还需 initdb、pg_ctl。 |
| IMS_PLATFORM_STORAGE_PRIMARY、IMS_PLATFORM_STORAGE_SECONDARY | 改成源平台文档主、副本的真实根目录。 |
| IMS_PLATFORM_LEDGER_ROOT | 同一平台实例的当前安全收紧账本目录。 |
| 模板中的交付、导出、通知、邮箱和审计归档路径 | 已启用的按源配置填真实路径，其余可留空。审计归档主、副目录需要一起填写。各持久目录不能互相嵌套。 |
| IMS_RESTORE_DB_URL | 隔离 PostgreSQL 实例的维护库连接，示例端口 55486。端口要与源数据库不同，库固定为 postgres。 |
| IMS_RESTORE_DB_USER、IMS_RESTORE_DB_PASSWORD | 隔离维护账号及密码，示例 restore_owner，需有建库及切换到恢复应用角色的权限。 |
| IMS_RESTORE_APP_USER、IMS_RESTORE_APP_PASSWORD | 隔离应用账号及密码，示例 restore_app，无超级用户、建库、角色管理权限。 |

## 2. 配置检查和完整备份

换掉以下三个路径。E: 只是示例，备份位置应在与源数据盘不同的物理盘。

~~~powershell
$repo = 'D:\IMS\information-management-system'      # 已迁移的项目根目录
$config = 'D:\IMS\config\maintenance.private.json'  # 填好的私有配置
$backupRoot = 'E:\IMS-backups'                      # 独立物理盘上的备份父目录
New-Item -ItemType Directory -Path $backupRoot -Force | Out-Null
.\Invoke-IMS-Maintenance.ps1 -Mode Check -Repo $repo -Config $config
~~~

核对 databaseReachable、requiredToolsPresent 和持久目录状态。用部署机原来的方式停止平台应用，保持源 PostgreSQL 运行，然后执行。

~~~powershell
.\Invoke-IMS-Maintenance.ps1 -Mode Backup -Repo $repo -Config $config -OutputRoot $backupRoot
~~~

看到 VERIFIED_BACKUP 后，记下打印的完整备份目录。整目录一起保管，其中包括 database.dump、文件副本和 manifest.json。暂不演练时，可恢复源平台服务。

## 3. 准备隔离 PostgreSQL

若已建好隔离实例，沿用它的端口和账号即可。否则使用以下示例命令。替换 bin 路径、全新数据目录、空闲端口和示例账号，并同步修改私有配置。

~~~powershell
$pgBin = 'D:\PostgreSQL\pgsql16\bin'                # 实际工具目录
$restorePgData = 'D:\IMS-recovery\postgres-55486'   # 全新数据目录
$restorePgPort = 55486                             # 隔离 PostgreSQL 端口
$restoreOwner = 'restore_owner'                    # 隔离维护账号
New-Item -ItemType Directory -Path (Split-Path -Parent $restorePgData) -Force | Out-Null
& "$pgBin\initdb.exe" -D $restorePgData -U $restoreOwner --auth=scram-sha-256 --encoding=UTF8 --locale=C -W
if ($LASTEXITCODE -ne 0) { throw '初始化隔离 PostgreSQL 失败' }
& "$pgBin\pg_ctl.exe" -D $restorePgData -l (Join-Path $restorePgData 'server.log') -o "-h 127.0.0.1 -p $restorePgPort" -w start
if ($LASTEXITCODE -ne 0) { throw '启动隔离 PostgreSQL 失败' }
& "$pgBin\psql.exe" -h 127.0.0.1 -p $restorePgPort -U $restoreOwner -d postgres
~~~

把初始化时设置的密码填写到 IMS_RESTORE_DB_PASSWORD。连接 psql 后执行下列命令。若更换了恢复应用账号，两处 restore_app 都需要替换。把交互设置的密码填到 IMS_RESTORE_APP_PASSWORD。

~~~sql
CREATE ROLE restore_app LOGIN NOSUPERUSER NOCREATEDB NOCREATEROLE;
\password restore_app
\q
~~~

## 4. 恢复演练

源平台应用保持停止，隔离 PostgreSQL 保持运行。如换了 PowerShell 窗口，先重新定义第 2 节的 repo 和 config 两个变量。脚本会创建恢复库和新的恢复子目录。

~~~powershell
$backup = 'E:\IMS-backups\20261115_220000_000'       # 改成第 2 节实际备份目录
$recoverRoot = 'D:\IMS-recovery\drills'             # 改成恢复输出父目录
$restoreAppPort = 18486                             # 改成空闲端口，与源应用端口不同
New-Item -ItemType Directory -Path $recoverRoot -Force | Out-Null
.\Invoke-IMS-Maintenance.ps1 -Mode RestoreVerify -Repo $repo -Config $config -Bundle $backup -OutputRoot $recoverRoot -RestoreAppPort $restoreAppPort
~~~

核对恢复输出目录的 restore-report.json。成功状态是 RESTORED_VERIFIED_NOT_OPENED，数据库记录摘要、文件摘要和当前账本复制应该通过。此时演练仅验证数据，尚未启动恢复站点。后续业务验收使用生成的 restored.private.json，先检查隔离端口、目录和保护配置，再实际验证公盘文件、档案附件和账号权限。完成演练后按原方式恢复源应用服务。

在独立介质上同时保管可取回的当前安全账本及恢复所需私有配置。脚本从 IMS_PLATFORM_LEDGER_ROOT 读取当前账本，校验实例、密钥和水位。包内备份时点的账本不能直接充当当前账本。
