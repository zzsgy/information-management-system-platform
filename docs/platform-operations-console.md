# 运维与数据保护管理

本批继续建设新平台的技术运维管理，面向电脑浏览器。沿用已验收的停机维护工具，不覆盖旧系统、旧预览数据库或历史备份。前台位于“管理中心 → 运维与保护”。

## 已实现的业务边界

- 保护检查：后台读取签名保护证据，分别检查公盘和档案读写边界，检查存储配对、Office 版本、扫描引擎和独立 PDF 子进程。探针为自行生成的空白 PDF，不含业务正文。任务完成与保护就绪分开显示；缺配置、不可用和保护失效均不能显示保护正常。
- 副本检查：对就绪及保留的历史原件逐个校验两份文件的长度和 SHA-256。每轮最多二十份，开始处理下一份前检查五秒时间预算；大文件使用已有流式摘要，文件 I/O 不占用数据库事务。记录实测时间、数量、异常码，不向 IT 页面返回原件名、磁盘路径或正文。
- 维护任务：真实排队、执行、完成、失败、取消、结果待核对状态；带版本的取消操作只适用于尚未执行的请求。失败后重新申请产生新任务、新目录，保留原记录。租约到期进入人工核对，不伪造成功结果。
- 独立备份：网页创建申请，源应用仍在线时保持“等待停机窗口”。独立执行器在停机后运行逐表锁定、数据库快照、文件复制和双副本核验；完整核验成功才登记备份点。
- 隔离恢复：只能选择已验证的备份编号，执行前重新核验备份摘要。固定写入另一 PostgreSQL 实例的新库、新目录；逐表和逐文件摘要一致后登记技术结论。原入口不切换，业务内容、附件对应及权限仍需复核。
- 每日计划：上海时区每日最多排队一次，默认暂停、默认保留三十天。保留期调整只作用于新备份，不缩短既有备份期限；本批不自动删除到期备份。排队时刻不是备份完成时刻。
- 业务文件任务：分页查看检测、转换、阅读及导出任务的最小状态。重试仍走原业务入口的实时授权，技术管理员不因此获得档案内容权限。
- 异常通知：保护异常、副本异常、备份失败、恢复失败及任务结果待核对接入现有安全事件和事务发件箱。同账号同类别一小时最多生成一条；钉钉正文只有固定类别、事件编号和平台入口，不发送文件名、路径或异常原文。

## 权限和接口

页面需要 `PLATFORM.OPERATIONS_MANAGE`。备份和恢复分别再要求 `PLATFORM.BACKUP_MANAGE`、`PLATFORM.RESTORE_VERIFY`。服务端与独立执行器均检查账号状态、授权代次、角色期限及明确拒绝优先；查看技术状态不会增授业务内容权限。操作沿用 HTTPS、CSRF、本人再验证、操作号去重和版本校验。

| 方法与 `/api/v1/admin/operations` 下的路径 | 行为 |
|---|---|
| GET 根路径 | 轻量运行摘要、最近保护检查、最新备份和计划；请求线程不扫描文件。 |
| GET `/lists/{section}` | `runs/backups/replicas/jobs`；每页二十条，支持状态筛选。 |
| GET `/runs/{id}` | 技术报告及任务详情，不含执行器秘密或任意路径。 |
| POST `/runs` | `kind/reason/sourceBackupId`；备份与恢复返回等待窗口。未知字段被拒绝。 |
| POST `/runs/{id}/cancel` | 提交处理依据和当前版本，只取消尚未开始的请求。 |
| POST `/runs/{id}/retry` | 提交修复依据和当前版本，生成新请求并关联原失败记录。 |
| PUT `/backup-plan` | 设置启用状态、上海时间小时、保留天数及依据；需要备份权限和当前版本。 |

V41 新增 `ops.maintenance_run`、不可变的 `ops.backup_point`、`ops.backup_plan`、`ops.replica_check`。维护队列与副本状态有索引；摘要读取分页，检查分批，外部 I/O 与短事务分开。每日计划用唯一键去重，任务执行用租约区分执行器。

维护工具本批补齐公盘 `drive` 模式的逐表锁定和恢复摘要核对。以前数据库备份包含该模式，但逐表校验清单没有覆盖它。

## 配置与执行

| 配置项 | 含义 |
|---|---|
| `IMS_PLATFORM_OPERATIONS_ENABLED` | 默认 `false`；启用本环境维护申请和后台检查。 |
| `IMS_PLATFORM_OPERATIONS_SCHEDULE_ENABLED` | 默认 `true`；隔离测试可关闭自动轮询，手动推进正式工作器。 |
| `IMS_PLATFORM_OPERATIONS_DELAY_MS` | 默认 `3000` 毫秒；检查轮询间隔。 |
| `IMS_PLATFORM_OPERATIONS_PROBE_DIRECTORY` | 专属私有探针目录；不能配置为原件、账本等持久目录。 |
| `IMS_OPS_RUN_ROOT` | 独立执行器私有根目录；每个请求固定使用其 UUID 子目录，不接受网页路径。 |
| `IMS_OPS_RESTORE_PORT` | 隔离恢复应用预留端口，不能与源应用相同。 |
| `IMS_RESTORE_DB_*`、`IMS_RESTORE_APP_*` | 另一 PostgreSQL 实例的维护身份和恢复应用身份；沿用既有维护工具的私有配置。 |

原有 `IMS_BACKUP_POSTGRES_BIN`、持久目录、TLS、账本和服务密钥仍由操作系统管理员在私有配置中维护。恢复结果关闭自动消息、维护、文件及通知工作器，内容保护保持未配置状态，防止演练恢复后自动发送或开放业务内容。

在源应用停机窗口执行：

```powershell
node scripts/platform/operations-runner.cjs --config D:/private/maintenance.private.json --run <任务UUID>
```

执行器不主动停止服务；服务在线返回 `WAITING_WINDOW`。重复执行已完成编号返回 `IDLE`。失败的目录和任务保留，重新申请产生新编号。私有配置、备份、恢复目录均不得提交到 Git。
