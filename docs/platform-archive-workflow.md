# 档案与流程模块：电子查看第一轮实现

后续管理配置、电子续借及站内到期提醒已另行开发，当前范围和验证见 [管理配置与电子借阅生命周期](platform-borrow-lifecycle.md)。本文保留2026年10月27日第一轮的交付边界与原始验收记录。

本轮在独立新平台中贯通电子档案登记、独立归档复核、基础开放申请、电子借阅审批和个人水印阅读。旧系统保留，测试只使用本轮新建的 PostgreSQL 数据库与合成 PDF。正文使用始终与档案目录管理权限分开。

## 已实现的业务闭环

1. 盒、件分别登记，服务端分配永久盒号和文件号；所属部门、等级及盒件关系由数据库约束。目录模板当前仅支持固定字段，不接受未定义扩展项。
2. 件先上传完整 PDF，经分片校验、双副本合并和文件检测后绑定候选修订。整理人员以本人身份确认实际页数及人工质量结论，再由所属部门负责人、档案超级管理员依次独立复核。检测通过不等于正式发布。
3. 候选检查单独绑定 `SCAN_QUALITY` 或当前 `REGISTRATION` 上下文，不产生正式阅读权。提交、节点推进、任职失效或版本变化会使旧候选阅读失效。
4. 安全题名检索、本部门一般文件基础查看、具体人员查看名单先提交基础开放申请，冻结受众、字段、修订、PDF 和期限，由真实必要节点批准后才生成策略或授权。重要、核心档案的基础开放还需公司总经理批准。
5. 电子借阅只开放 `VIEW`，整批最多 50 个不同文件；展开盒清单后冻结文件、版本、动作和原批次最高等级，按所属部门拆分子单。子单继承原最高等级，不能通过拆单降低路线。
6. 受控阅读只返回本人水印 PNG，不提供源 PDF 下载地址。每次读取重新检查当前账号、会话、模块角色、固定批准来源、版本、有效期、保护证据和两个文件副本。
7. 撤销指定人员批准来源或基础开放策略均保留历史，立即使相应旧来源失效，并提升受影响员工的授权代次。单一来源撤销不会删除其他独立批准。电脑端在会话失效时清除阅读图像。

## 固定审批规则

| 整批最高等级 | 一般跨部门电子查看路线 |
| --- | --- |
| 一般 | 申请部门档案员 → 申请部门负责人 → 所属部门负责人 → 所属部门档案员 → 档案超级管理员 |
| 重要 | 申请部门档案员 → 申请部门负责人 → 所属部门负责人 → 所属部门档案员 → 公司总经理 → 档案超级管理员 |
| 核心 | 申请部门档案员 → 所属部门档案员 → 所属部门负责人 → 公司总经理 → 档案超级管理员 |

同部门档案员节点仅按既定规则去重，档案员本人申请可跳过自己的档案员节点。其他必要职责不因同一人兼任而合并。申请人与必要审批人相同则暂停办理，管理员只能改派给当前合法、非申请人的职责持有人，不能跳过节点。部门负责人和公司总经理来自独立组织任职，公盘角色不能充当档案批准职责。

平台首次建库的 IT 通用账号（具有有效平台 IT 管理员任职）发起电子或纸质借阅及续借时，每张部门子单仅安排一位其他档案超级管理员审批。纸质交付及续借完成时沿用该申请的审批路线，累计超过七个自然日也按这一节点办理。

一般本部门电子查看在未取得基础开放时走本部门档案员、部门负责人、档案超级管理员路线；重要本部门在管理员之前增加总经理。每个决定、路线快照、候选修订和人工质量证明均保留，不覆盖历史。

## 日历与失效核验

新申请按双休及国务院办公厅公布的年度放假、补班安排计算。电子借阅默认从授权生效次日计算 3 个工作日，截止当日上海时间 23:59:59，单次最多 30 个自然日。此前送审的申请沿用原日历版本，已经批准的截止日期继续使用已保存的值。

授权有效性不只检查 `ACTIVE`：还要求同一业务、固定原路线、每个必要节点的真实在线批准及原快照一致。过期、驳回、撤回、当前任职失效、版本替换或批准字段扩大均不能继续发放正文。送审时间先统一为数据库微秒精度，防止 Java 与 PostgreSQL 在半微秒边界舍入不一致。

## API 与实现边界

核心接口均位于 `/api/v1`，错误响应使用统一包装和请求号。写入要求真实会话、CSRF 和操作号；管理、复核和撤权还要求绑定对象与动作的一次性本人再验证。需要并发控制的决定、撤销和候选绑定校验 `X-Expected-Version`。

| 功能 | 接口 |
| --- | --- |
| 目录查询/登记 | `GET/POST /archive/records`、`GET/POST /archive/boxes` |
| 候选绑定/人工质量/送审 | `POST /archive/records/{id}/pdf-versions`、`POST /archive/quality-checks`、`POST /archive/registration-reviews` |
| 基础开放申请 | `POST /archive/access-policy-requests` |
| 电子借阅/进度 | `POST /archive/borrow-batches`、`GET /archive/borrow-batches/{id}` |
| 待办/决定/合法改派 | `GET /portal/tasks`、`POST /workflow/steps/{id}/decisions`、`POST /workflow/steps/{id}/reassign` |
| 本人申请/撤回 | `GET /portal/requests`、`POST /archive/borrow-requests/{id}/withdraw` |
| 阅读 | `POST /archive/view-sessions`、`GET /archive/view-sessions/{id}`、`GET /archive/view-sessions/{id}/pages/{page}` |
| 授权摘要/撤销 | `GET /archive/access-grants`、`POST /admin/archive/access-grants/{id}/revoke`、`POST /admin/archive/access-policies/{id}/revoke` |
| 组织职责 | `PUT /admin/departments/{id}/management-duties`、`PUT /admin/company-duties/general-manager` |

安全题名表示不投影真实题名、摘要、关键词或版本；搜索在授权过滤之后匹配和分页，不能通过秘密字段命中推断档案。目录管理不自动赋予正文权，IT 管理和公盘权限均不能借道读取。单次归档复核当前接收一个盒或件对象，避免将跨对象部分成功伪装为整体成功。

纸质借还、下载/打印、续借、交接证据补录、任意流程编排、扩展目录字段及完整管理配置页面留待后续批次，当前接口不会伪装支持。工作流事件已与业务事务同写 outbox，尚未接入真实邮件或站内通知投递。

## 性能、保护与扩展

- 授权过滤、计数和分页在 PostgreSQL 执行；固定清单和复合索引限制扫描范围，列表不加载 PDF。
- 盒号/文件号使用原子流水分配；流程及授权使用短事务、行锁、版本比较和操作回执。独立档案命令边界避免所有借阅串行占用 IAM 全局配置锁。
- 文件分片有界处理；档案与公盘共享两个隔离 PDF 工作器名额，每个进程限制内存和运行时间，避免各模块分别放大进程并发。
- 双副本在解析前后核验摘要；最终短事务再次核验批准并取得库外逐页刷盘回执，未取得回执不交付图像。
- 数据库迁移 V8–V14 增加不可覆盖历史及业务约束，策略、借阅、候选和流程使用独立服务与扩展接口。

`IMS_PLATFORM_SCANNER_ARCHIVE_SERVICE_ID` 必须配置独立、当前有效且获准实际部门的档案检测服务身份。保护证据仍需部署方独立签发，不能由业务审批代替真实备份和主备核验。
