# 目录更正、撤下与保管提醒

本批在独立平台中补齐已发布档案的维护闭环。入口为电脑端 **目录与保管**，包含文件目录、档案盒、保管到期和目录模板。现有电子借阅、下载打印、纸质交付归还继续使用原业务入口。

## 业务规则

| 事项 | 生效方式 | 保留内容 |
|---|---|---|
| 关键词、摘要、备注、非关键分类字段 | 有权管理人员确认本人身份后直接更新，记录前后值并通知 | 原批准修订及全部历史 |
| 名称、编号、归属、等级、期限、模板等关键内容 | 固定候选，经所属部门负责人、独立档案管理员逐级复核 | 批准前现行版本；批准后旧版本和旧审批 |
| 完整 PDF 更正 | 实际文件检测、双副本验证、真实页数解析、逐页人工确认后，进入关键更正审批 | 原 PDF 字节、候选、修订和审批证据 |
| 申请撤下 | 独立档案管理员复核后停止正常检索和使用 | 目录、历史原件、在途纸质占用及后续归还 |
| 保管期限到期 | 到期前 30 天及到期阶段提醒，清单按现任管理范围显示 | 不自动撤下、不自动销毁 |
| 分类模板修订 | 配置管理员创建新的不可变版本；旧版本可停用 | 旧档案的原定义与字段值 |

关键更正生效后，旧阅读、下载、打印批准不会覆盖新的目录修订或 PDF。旧授权记录保留用于追溯，新的使用须重新获批。整盒等级或部门更正同步作用于冻结成员，审批页面明确显示涉及件数。普通编辑不无故使既有批准失效。

部门、所属盒调整仅作为有原因、经审批的目录纠错。源盒存在在途纸质借阅或待交付批准时拒绝调整归属；撤下本身允许保留在途借还，实际归还和复核仍可完成。撤回事项保留已发生的节点决定，不删除历史。

保管到期日以实际存档日期加日历年计算，闰年日期按日历规则处理；永久保管不生成到期日。编号更正或移盒后，原盒号、文件号及盒内件号仍保留占用，禁止分配给其他对象。

## 档案页登记与草稿维护（2026-11-02）

- 档案查询页提供“文件目录 / 档案盒”页签，盒、件列表分别搜索和分页；档案盒每页20条，总数来自服务端。
- “批量登记”以及单条登记弹窗中的 Excel 入口复用台账接收流程。下载当前模板，填写 BOX / RECORD 行；新盒使用 `rowKey`，同批文件使用 `boxKey` 关联，也可通过已有 `boxNo` 追加文件。每批最多1000行，全部预检通过后整批新增；任意一行失效则整批回滚。登记不会自动完成质量确认或归档复核。
- 未发布草稿可从列表“修改 / 删除”办理；修改须有原因和原版本，保留旧目录修订及已有 PDF，生成新候选后须重新确认质量。编号、部门、等级、所属盒保持原登记归属。
- 删除仅将草稿标记为撤下，从正常列表移除，编号、原件、历史及审计保留。盒内仍有未撤下文件时拒绝删除档案盒。
- 在审对象、已有扫描交接的文件，以及所属盒正在复核或更正的文件，需先处理原流程。已归档资料通过“更正 / 申请撤下”办理，继续执行必要审批。
- 草稿入口为 `PUT /archive/catalog/{type}/{id}/draft`（`changes`、`reason`）及 `POST /archive/catalog/{type}/{id}/delete`（`reason`）；均要求当前维护权限、本人再验证、操作号和 `X-Expected-Version`。

本次回归使用隔离库：目录维护完整回归23项、最终草稿专项5项、批量接收8项及台账解析10项通过；前端16项测试及类型检查通过。浏览器实测单条盒件登记、文件修改删除和分页列表。证据位于工作区同级 `tmp/archive_registration_20261102/`。浏览器扩展未开启本地文件访问，因此批量上传的全链路通过真实上传、检测和导入服务集成测试验证。

## 字段模板

支持文本、数值、日期、是/否及单选字段；可配置中文名称、稳定代码、必填、关键性、列表显示、维护检索、启停和顺序。每版本最多 50 个字段，每个单选字段最多 100 个选项。

基础业务字段不能被扩展字段覆盖。已有字段不能删除、改变类型或降低关键性；可停用但必须保留原值。旧档案继续绑定原模板，切换模板本身属于关键更正。字段查询仅在当前有权维护范围中进行；列表显示和查询开关分别生效，不能以分类字段绕过部门权限。

## 实现和运行边界

- 后端服务：`CatalogMaintenance`、`CatalogTemplates`；HTTP 入口为 `CatalogMaintenanceController`。输入字段、类型、长度、状态和本人权限均由服务端核验。
- 列表、版本及更正历史由数据库分页，每页最多 100 条；历史列表仅取摘要，打开事项才解析完整对比。字段模板列表直接投影已有查询结果，避免逐个重查。
- 历史、到期及未完成事项建有索引；每个对象最多一条未完成更正。整盒快照最多 1,000 件，超限拒绝操作，避免无界长事务。包含式关键词检索仍需在正式数据规模下评估查询计划与容量。
- 本人确认、稳定操作号、请求载荷校验、行版本和固定锁顺序共同保护重复提交及并发审批。审批每一节点重新检查申请人权限、当前职责、原对象版本及固定成员。
- 新原件沿用检测、双副本校验和受控阅读服务；候选阅读只能使用本次更正的专用上下文，不代表取得正式正文使用权。
- 关键变更增加数据库 `catalog_epoch`，同时写入已有库外安全账本。会话和后台身份读取均核对水位，旧数据库恢复不能重新开放撤下对象或旧版本。
- 安全账本先于数据库提交收紧。如果账本已写入而数据库提交失败，会保持拒绝访问状态，须按恢复流程核对并恢复一致水位；不得清空账本规避检查。
- 到期消息接入既有业务通知和有限次重试队列。事件按对象、期限、接收人及阶段去重；通知不携带档案题名或正文，投递时重验现任范围。

本批没有新增生产连接密钥或默认密码。数据库增量迁移为 V22、V23，分别增加维护结构和修正通知的当前部门核验；不要修改已执行迁移。独立平台继续使用 `platform` 构建配置，先执行 `web` 的 `npm run build:platform`，再运行后端 `mvn -Pplatform verify`。后端单独构建不等于已更新网页。
