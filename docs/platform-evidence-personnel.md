# 审批凭据补录与人员交接

本批接续目录维护与保管模块，依据需求 V0.5、接口及数据库设计 V1.1 实施。代码位于 `backend/` 和 `web/src/platform/`，界面仅面向电脑端。历史系统、已有数据库及附件保持原状。

## 已接通的业务

1. 申请人在“流程中心 → 我的借阅 → 查看进度”中，为当前部门负责人或总经理节点提交既有同意凭据。支持 PDF、JPG、PNG、MP3、M4A、WAV、AMR，每次 1–10 份，每份最多 50 MiB。复用分片、双副本校验、真实文件类型检测及扫描链；只有 `COMPLETE/READY` 原件才能关联。提交不推进审批。
2. 具有 `PLATFORM.EVIDENCE_RECORD` 的 IT 在“凭据补录”核对实际同意人、同意时间、固定对象版本、使用动作和期限，读取原件后进行本人密码再验证，只补录对应当前节点。原同意人和实际经办人分列，后续必要节点继续办理；本人回避、已驳回、已结束、任职变化和范围变化均拒绝。
3. 档案超级管理员在“人员交接 → 档案员交接”先预览，再提交固定清单摘要、批准依据和原因。一次事务结束原档案员任职、建立接任任职、移动未完成及尚未激活的必要节点，并移交未完目录事项。接任人无需提前占用唯一档案员职位。原创建人及完成决定不改写，个人借阅授权不转移。
4. IT 在“人员交接 → 员工转岗”查看原有角色、个人授权、在审事项及在途实物数量。提交时回收旧角色、个人权限、公盘个人授权、档案个人授权和旧阅读会话，结束需重新核定的本人申请，更新部门并立即结束旧登录。新岗位权限仍通过已有角色管理按批准依据配置。已交接给新经办人的目录事项继续办理；原件借出历史和归还责任保留。

## 权限与固定证据

| 操作 | 权限及范围 | 关键边界 |
| --- | --- | --- |
| 上传、提交凭据 | 具备档案入口的原申请人，当前允许补录节点 | 原件必须属于本人、该节点及 `ARCHIVE/EVIDENCE` 用途；拒绝其他上下文原件 |
| 核验队列、补录 | 当前有效 `PLATFORM.EVIDENCE_RECORD` | 不授予档案全文、目录维护或其他模块权限；不能补录本人申请或替自己记录同意 |
| 读取凭据原件 | 获权 IT、仍有合法职责的原同意人、具有档案审计能力的超级管理员 | 每次检查当前身份、保护状态、原件状态及双副本摘要；无公开文件地址 |
| 档案员交接 | 档案超级管理员及 `ARCHIVE.CONFIG_MANAGE` | 同部门有效接任人、唯一档案员、固定事项摘要；本人回避冲突整体拒绝 |
| 员工转岗 | 当前 `PLATFORM.USERS_MANAGE`，本人再验证、账号版本 | 禁止自己转岗；未交接档案员及尚未结束的组织审批职责须先处理。2026-11-04 用户明确取消最后管理员数量保护 |

同意时间和补录时间分别保存。既有同意可以早于系统填单，但必须发生在原同意人的本次真实任职期间，且不能晚于服务器当前时间。附件绑定申请、节点、任职引用、节点版本及不可变业务快照，不能靠替换正文或改变操作号绕过核验。

审批证明函数同时认可在线决定和具备完整固定证据的补录决定。补录先保存不可变决定及已使用证据，再通过与在线审批共用的节点推进方法生成结果或最终授权。通知只发送给原同意人和申请人，内容只包含安全状态引用。核验退回不等于业务驳回；申请人可撤回待核验材料后重新提交。

## Service API

所有路径位于 `/api/v1`。写入复用 `X-Operation-Id`；要求版本的接口使用 `X-Expected-Version`，高风险操作另带绑定具体对象和动作的 `X-Reauth-Token`。

| 路径 | 用途 |
| --- | --- |
| `POST /workflow/steps/{id}/evidence` | 提交最多 10 份已检测凭据；不自动批准 |
| `GET /workflow/steps/{id}/evidence` | 本人或合法节点处理人的提交记录 |
| `GET /admin/workflow/evidence` | IT 按状态分页核验队列，每页上限 100 |
| `GET /workflow/evidence-submissions/{id}` | 有权人员读取固定范围和核验记录；目录更正附前后值，基础开放附受众范围 |
| `GET /workflow/evidence/{id}/content` | 原始二进制；支持单区间 206，非法区间 416，响应禁止缓存 |
| `POST /workflow/steps/{id}/evidence-decisions` | `WORKFLOW_STEP / EVIDENCE_RECORD` 再验证，仅补当前节点 |
| `POST /workflow/evidence-submissions/{id}/reject` | IT 核验退回，绑定 `WORKFLOW_STEP / REJECT_EVIDENCE` |
| `POST /workflow/evidence-submissions/{id}/cancel` | 原申请人撤回待核验提交 |
| `GET /admin/archive/archivist-handover-options` | 档案超级管理员选择部门和本部门接任人 |
| `POST /admin/archive/archivist-handovers/preview` | 固定待办、目录事项、人员代次及在途数量，生成摘要 |
| `POST /admin/archive/archivist-handovers` | `DEPARTMENT / HANDOVER_ARCHIVIST` 再验证及摘要校验，原子交接 |
| `GET /admin/workflow/assignment-events` | 受权超级管理员按部门或交接批次分页读取事件 |
| `GET /admin/personnel-department-options` | IT 可选的有效部门名称 |
| `GET /admin/users/{id}/department-change-preview` | 仅人数及数量层面的转岗影响，不泄露档案题名或正文 |
| `POST /admin/users/{id}/department-changes` | `USER / CHANGE_DEPARTMENT` 再验证与账号版本，转岗和撤权同事务 |

## 数据、性能及故障边界

- 新增迁移 `V24__evidence_and_personnel_continuity.sql`，不改已执行旧迁移。新增凭据提交、原件引用、档案员交接、部门变更四类记录；目录事项增加独立经办人，创建人保持不变。原始附件、交接记录、完成决定使用不可覆盖约束，新增字段均有中文说明。
- 核验队列按状态、时间和标识建索引，未处理提交对节点设置唯一约束。分页在数据库执行。每份原件上限 50 MiB，顺序上传，浏览器不同时摘要十份大文件。音频检查验证容器及音频帧结构，不代表音质或录音真实性鉴定；真实性由 IT 对既有同意承担核验责任。
- 补录与在线审批采用相同账号、实物盒、流程和节点锁序；节点唯一决定和幂等回执防止重复批准。交接与固定路线创建协调，避免新流程在交接间隙绑定旧任职。一次交接最多 1000 个节点和 1000 个目录事项，超过上限明确拒绝，不截断清单后报告完成。
- 任职与事项在同一数据库事务内更新。身份安全收紧同时写入独立安全账本；账本已经推进但数据库后续失败时，旧身份按失效方向关闭，需按既有运维流程核对后恢复，不会自动回退旧授权。
- 原件读取及补录均验证两个副本，任一副本异常停止交付或补录。沿用既有保护门槛；本机两个目录不能作为跨机器故障域或独立备份的验收证明。
- 转岗不会宣称收回已经下载或打印的资料。已借出的实物仍由原借阅人承担归还责任；重新配置合法档案入口后才能继续使用个人办理页面。
