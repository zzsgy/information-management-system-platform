# 在线编辑退出、登录失效与重开修复

2026-11-02，用户在重新进入WPS来源DOCX编辑时遇到“上次协作尚未结束或最终保存待确认”。这次不是证书错误。

## 已确认事实

旧编辑批次`c29d4422-6a39-4199-a68d-724d2c60b054`创建于09:45，绑定登录最后活动时间09:44，10:23重新登录使旧登录撤销。账号、编辑权限、文档协作开关及编辑代次都仍有效，但旧登录代次24与账号当前代次25不同。该批次没有保存请求或候选稿件，原生文档服务`info`返回无在线参与者，平台仍保持`UNKNOWN`。

原处理把“关闭且没有修改”与“有内容需要保存”放在同一个旧登录有效性条件下。旧登录过期时，即使文档服务确认无修改，也无法结束会话，导致后续登录一直被旧批次阻塞。此前浏览器验收主动等待会话CLOSED后才重开，漏掉了用户立即返回和登录失效场景。

## 修复

1. 对已经通过签名和固定编辑key验证的原生状态4回调，只结束会话，不写文件版本，因此不再要求旧登录仍然有效。`OPEN/CLOSING/UNKNOWN`可结束为`CLOSED`，活动参与记录改为已离开，追加一次关闭审计；重复回调保持幂等。
2. 只要存在`REQUESTED/RECEIVING/UNKNOWN`保存回执，仍阻断自动关闭，不清除、不接受待确认稿件。已撤销会话及参与关系保持撤销，关闭流程不恢复账号或权限。
3. 用户当前有阅读与编辑权限时，再次进入旧的`CLOSING/UNKNOWN`批次会先请求文档服务重发真实状态。此网络请求放在数据库行锁之外，让回调能够正常结束旧批次；不根据“没有在线用户”自行伪造关闭或丢弃内容。
4. 最终保存尚在进行时返回明确的`OFFICE_FINAL_SAVE_PENDING`。页面短暂等待，并重新读取最新文件版本后加入，最多等待30秒；真正需要处理的未知保存结果仍引导用户查看协作与保存记录。

原生状态4定义及`info`重发状态行为依据[ONLYOFFICE回调说明](https://api.onlyoffice.com/docs/docs-api/usage-api/callback-handler/)和[info命令说明](https://api.onlyoffice.com/docs/docs-api/additional-api/command-service/info/)。
