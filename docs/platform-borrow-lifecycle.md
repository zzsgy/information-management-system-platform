# 管理配置与电子借阅生命周期

本轮延续独立平台及新库，增加电脑端管理配置、关联原批准的电子续借、站内到期提醒和到期状态处理。旧系统、原数据库和附件不切换。本轮仍只办理电子 `VIEW`，纸质借还及下载/打印留待后续批次。

## 电脑端配置

- **组织审批职责**：平台组织管理者维护部门负责人、分管领导与公司总经理；候选只返回有效档案员工的姓名、工号和标识，负责人限定本部门。任职保存原因、批准依据和历史记录，变更使受影响员工旧登录失效。平台组织权限不自动赋予档案配置或正文权限。
- **工作日**：新申请按双休和国务院办公厅公布的放假、补班安排计算。年度数据随程序更新，系统按本次借期实际需要的日期检查覆盖，旧申请仍读取提交时绑定的日历。
- **档案授权配置**：从配置入口进入具体文件基础开放申请，可选择安全题名受众、本部门一般文件查看、指定人员名单和期限。具体人员最多50人且必须有截止日期；批准前不发权。人员选择必须先验证具体文件目录管理范围，IT 或他部门档案员不能借道检索。已批准来源及基础策略在流程中心分别撤销。

组织职责变更不跳过必要节点。原处理人失去任职后，由档案配置管理者显式交接到当前合法人员；同一员工重新任命产生新任职记录时，也可交接到其新记录，保留交接历史。申请人仍不能审批自己的必要节点。

## 续借业务与期限

1. 原借阅人选择原批次发起续借，只能填写期限、用途和原因，不能改变清单、动作或指定路线。原批次仍有部门待审时不能续借；部分批准批次仅承接已批准范围，保留原父批次最高等级。
2. 每项冻结原授权、目录修订、PDF、原截止与来源版本。提交时原授权必须实际有效；换版、撤权、申请人部门变化或批准来源失效时拒绝沿旧单续借。
3. 待审及驳回均不延长原授权。原授权到期后旧阅读立即停止；已经在途的续借可以继续走完整审批，但只有真实批准后才建立新授权。
4. 必要路线采用原最高等级与当前要求的严格规则。申请人后来成为档案员，也不能因此省略原路线中的档案员节点；本人重合时仍须合法交接。
5. 最后一个必要节点批准后另建借阅授权，关联原来源，不回写原截止。未到期时从原截止日继续计算续借天数；在途审批已跨原截止时，从本次批准生效日计算。按本次申请的计日规则计算，单次新授权最长30自然日，结果必须确实延长原截止。
6. 原阅读地址固定原来源，不因存在新批准而自动延长；原来源到期后重新打开阅读，才能按新批准建立新的本人阅读会话。

每个原批次最多保留一个待审或成功续借。相同操作号和相同内容重放原结果，改变内容返回409；不同操作号并发提交，由原批次行锁及数据库唯一索引限制为一个结果。驳回或撤回后可重新申请；成功后须关联最新批准批次继续续借。

到期归档为 `EXPIRED` 后，安全管理员仍能明确撤销其作为在途续借依据的资格。新续借不因原来源时间自然到期而提前生效，也不能沿已撤权来源继续扩权。

## 到期与提醒

- 每次创建阅读、查看阅读状态和交付页面均按服务端当前时间核验。到期实际失效不等待调度、通知或状态清理。
- 后台每轮最多处理200项到期状态、200条过时提醒及200条新提醒，多实例竞争事务咨询锁，进程退出或事务失败后释放锁；同一提醒以接收人、子单、原截止和提醒偏移去重。任务开始及提交前都核验当前可写节点保护事实，证据失效时跳过或回滚；实时到期失效不等待该任务。
- 电子借阅在上海时区到期前一天及当天投递**站内提醒**。通知只包含批准截止和受控业务引用，不包含秘密题名、摘要或源PDF位置。
- 投递和查看共用当前来源检查。续借生效、撤权或期限变化后，旧提醒立即从当前列表隐藏，后台保留取消记录。重复确认已读保留首次时间，不改变授权。
- 已存在有效新续借时，不重复提醒其替代的原来源。站内通知通过数据库事务持久化，失败重跑不重复执行业务决定。本轮未发送真实公司邮件、短信或钉钉消息。

## API与配置

接口前缀 `/api/v1`，沿用真实会话、CSRF、请求号及操作号。配置写入、组织职责和合法交接还要求绑定对象与动作的本人再验证。所有读取按实际主体范围裁剪。

| 功能 | 接口 |
| --- | --- |
| 当前组织职责与候选 | `GET /admin/organization-duties`、`GET /admin/organization-duties/candidates` |
| 组织职责维护 | `PUT /admin/departments/{id}/management-duties`、`PUT /admin/company-duties/general-manager` |
| 具体文件基础授权人员候选 | `GET /archive/access-policy-subjects` |
| 续借 | `POST /archive/borrow-batches/{id}/renewals` |
| 进度与实时使用状态 | `GET /archive/borrow-batches/{id}`，审批状态与 `usageState` 分开 |
| 本人站内通知与已读 | `GET /portal/notifications`、`POST /portal/notifications/{id}/read` |

新增迁移 `V15__borrow_lifecycle.sql` 和 `V16__archive_assignment_entry_guard.sql`，保留既有迁移校验值。新增关联、唯一约束、到期索引和站内通知表均包含中文说明。当前合法处理人还须与实时登录入口采用相同的公司范围角色及个人明确拒绝优先规则，不能只凭角色名称参与审批。

JSON 请求正文上限为64KiB，上传分片上限为8MiB。

| 环境变量 | 缺省 | 作用 |
| --- | --- | --- |
| `IMS_PLATFORM_BORROW_LIFECYCLE_ENABLED` | `false` | 显式启用到期状态与站内通知调度；正式配置时应开启 |
| `IMS_PLATFORM_BORROW_LIFECYCLE_DELAY_MS` | `60000` | 调度间隔，单位毫秒；本轮浏览器隔离验收设为1000 |

借阅列表和通知先在数据库按授权过滤，再计数分页；新任务排除已生成的同期限通知后再限制批量，避免前200条重复记录阻塞后续通知。PDF仍复用已有全局有界隔离进程，管理配置和提醒不创建额外渲染工作器。
