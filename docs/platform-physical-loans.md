## 业务行为

| 环节 | 当前实现 |
|---|---|
| 登记 | ELECTRONIC / PAPER / MIXED 载体；纸质和混合原件必须有真实存放位置。纯纸质文件以原件质量确认归档，不上传占位 PDF；混合文件仍须有通过检测和复核的完整 PDF。 |
| 原件 | 一盒或一件对应一个实物标识，数量为 1；盒内纸质文件数由登记结果累计，不能靠手填数量创建虚构原件。原件位置维护留有事件记录。 |
| 申请 | `BORROW_PHYSICAL` 独立审批；最多展开 50 份不同文件，不得同时选择整盒和其分件。按所属部门拆单，保留父批最高等级与固定日历、版本和成员。 |
| 批准 | 初借批准后仅待交付，不产生占用或电子查看、下载、打印授权。题名开放只能提供已批准的安全题名。 |
| 交付 | 有本部门目录和实物管理职责的非借阅人经办；实际时间不能在未来或早于必要批准。重验借阅人资格、冻结目录版本、完整成员和占用。实际交付成功才生成占用。 |
| 占用 | 整盒与分件互斥；不同分件可分别借出。借出期间禁止相关原件位置变更及盒内增件。逾期、归还声明和异常复核均不释放占用。 |
| 归还 | 本人提交归还声明后，由非借阅人本人且具备实物复核权限的档案超级管理员核对实际收到时间、数量、附件、完好情况。全部通过才释放占用；少件、未收齐和损坏可登记异常并保留占用。 |
| 续借 | 关联同一笔实际借出，保留实际交付日、原件和原最高等级；待审或驳回不改原截止。批准后从原截止与批准时刻中较晚者起算，单轮最多 30 个自然日。 |
| 七日规则 | 从实际交付日按上海日期计算累计期限，超过 7 个自然日需所属部门分管领导真实批准。交付跨日、续借审批拖延触发补批时，在同一流程追加关联路线和领导节点，保留原决定，补批前不交付或扩期。 |
| 提醒 | 使用共享生命周期开关，生成临近到期、当日到期和逾期站内事项；按原件、接收人、截止、种类及日期去重。续借或实收后旧提醒失效；提醒不改变占用。 |
| 结束 | 一子单内全部计划原件均实际交付且全部实收归还，才结束相应原申请和续借；历史决定、原件范围与事件保留。 |

## 电脑端入口

档案中心登记盒件、核对质量、送归档复核及申请安全题名开放；流程中心办理必要审批、本人回避和任职失效后的合法改派。新增“实物借还”入口，提供分页实物台账、待交付清单、借还记录及本人提醒，支持实际交付、原件续借、归还声明、异常复核和实收确认。

纯纸质对象不提供电子申请复选入口；安全题名视图不返回库位及完整编号，也不能通过猜测完整编号命中检索结果。归还确认要求经办人主动勾选附件及完好核验，不自动勾选。

2026-11-05：借还详情收起后保留原件、借阅人和进度摘要，展开时重新读取详情。从待办进入他人的借还记录时，默认显示已授权的经办范围。详情分为借阅申请、实物交接、归还与复核记录；题名沿用原申请的可见内容，整盒可展开查看原申请固定的文件清单。归还待复核时提示核对原件、数量、附件及完好情况，只有确认实收后显示已归还。

## Service API

所有接口位于 `/api/v1`，沿用 HTTPS、当前有效登录、CSRF、统一请求标识及模块权限。写接口使用 `X-Operation-Id`；位置和归还操作另须当前 `X-Expected-Version`。敏感交付、位置和实收复核使用绑定实际对象、精确动作的一次性 `X-Reauth-Token`。重复操作号相同载荷返回原结果，异体载荷冲突；待补批交付允许沿原操作号更新实际交付时刻，其他范围固定。

| 方法与相对路径 | 输入及权限边界 |
|---|---|
| GET `/archive/physical-items` | `page/pageSize/keyword/boxId/recordId/available`；先授权过滤再计数和分页，单页最多 100。 |
| PATCH `/archive/physical-items/{id}/location` | `location/reason`；本部门实际管理权限、版本号和本人再验证，相关借出存在时拒绝。 |
| POST `/archive/borrow-batches` | `form=PAPER/actions=[BORROW_PHYSICAL]/purpose/items[{physicalItemId}]/period`；本人纸质申请资格、可见范围和 50 文件上限。 |
| GET `/archive/physical-delivery-requests` | `page/pageSize`；本人申请或合法经办范围，单页最多 100，待补批返回原完整操作范围。 |
| POST `/archive/borrow-requests/{id}/deliveries` | `physicalItemIds/actualDeliveryAt/actualQuantity/condition`；数量等于本次盒件标识数，最多 50；可能返回 `WAITING_APPROVAL`，该状态无占用。 |
| GET `/archive/physical-loans` | `page/pageSize/scope=MINE或MANAGE/state`；本人或合法经办范围。 |
| GET `/archive/physical-loans/{id}` | 本人或合法经办人查询借出及最近 50 轮归还、100 条事件；标识不授予权限。 |
| POST `/archive/physical-loans/{id}/return-requests` | `actualQuantity/condition/note?`；本人申报 0 或 1 盒件，生成待核验轮次。 |
| POST `/archive/physical-loans/{id}/return-reviews` | `returnRequestId/result/actualReceivedAt/actualQuantity/condition/allAttachmentsConfirmed/intactConfirmed`；实收确认须数量 1 且两项核验均为 true。 |
| POST `/archive/physical-loans/{id}/renewals` | `purpose/reason/period`；本人、有效原批准、同一原件，无其他待审续借或待归还复核。 |
| GET `/archive/physical-notifications` | 本人且仍有相应借阅或经办范围的最近 100 条有效事项，不提供全公司实物明细。 |

非法身份或范围拒绝访问；版本、占用、重复异体及失效来源返回冲突；缺必要保护或回执失败时拒绝写入。表单状态不作为批准或实收证据。

## 并发、保护与扩展

- 身份按 UUID 顺序锁定，实物操作先按盒 UUID 锁盒，再按原件 UUID 锁行；纸质审批决定也遵循身份后盒的顺序。整盒与分件竞争在同一盒锁内校验，当前单件占用另有部分唯一索引。
- 原件、截止和本人通知有索引；台账、借出和交付清单分页，交付待补批信息整页批量查询；提醒每轮最多 200 笔，事务级咨询锁防止多实例重复调度，已通知记录不阻塞后续批次。
- 固定原件范围、借出关联、交付关联和业务事件使用数据库不可改写触发器；补批产生新关联路线，不覆盖原审批快照。续借不创建第二笔占用。
- 实际交付和实收复核先将库外意图回执独立刷盘，再提交业务事务；回执失败时回滚。该回执证明服务器接受记录的意图，不能代替现场人员核实实际交接。
- 沿用 `platform.borrow-lifecycle.enabled`（默认 false）及 `platform.borrow-lifecycle.delay-ms`（默认 60000 毫秒）；开启后同时调度电子生命周期和纸质提醒。正式部署须配置真实组织职责、公司工作日历、保护事实和独立回执目录。
- 本批未接入扫描枪、门禁、打印机硬件、邮件或手机端；正式病毒库、生产双节点切换、备份恢复及生产负载压测须另行验收。
