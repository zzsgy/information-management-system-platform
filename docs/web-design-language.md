# 信息管理系统网页设计语言

员工要能辨认自己在哪个页面、先看什么、下一步能做什么。平台工作台、独立档案工作台和受批打印入口共用颜色、字体与控件层级；页面结构随任务变化。

## 页面如何组织

| 页面类型 | 信息顺序 | 项目里的例子 |
| --- | --- | --- |
| 身份与入口 | 标明系统身份，突出当前步骤。登录、首次设密和找回密码分别显示各自的说明与主按钮。 | 登录、账号设置、身份复核 |
| 工作台 | 摘要使用员工实际可见的数据。桌面把待办放在主栏，公告和常用网站在旁，窄屏按处理顺序阅读。 | 员工首页、旧版档案工作概览 |
| 检索与台账 | 标题和主要操作在前，筛选紧邻结果。每行优先呈现业务名称，再呈现归属、状态和时间。刷新、总数和翻页位置保持稳定。 | 公盘、档案、公告、会议、人员、操作日志 |
| 办理与编辑 | 先交代办理对象和当前状态，再展示可填字段、附件和操作。相关字段分组；校验反馈留在当前表单内。 | 借阅审批、会后事项、员工反馈、凭据提交、配置弹窗 |
| 管理与运维 | 按管理对象分组导航。状态摘要、明细数据和会改变配置的操作各有位置，危险操作使用明确动词与危险状态色。 | 组织与角色、扫描和导入、服务、备份、安全与审计 |
| 阅读与输出 | 工具栏负责文件名、页码、缩放和操作；正文占据主要空间。文档底色、企业信纸、水印和纸张方向遵循原件或批准清单。 | 公告信纸、公盘与档案阅读器、Office 编辑外框、受批打印 |

## 共同的视觉规则

- **排版与对齐**　页面标题、区块标题、业务内容、辅助说明构成四层。名称可以换行，日期、页码和数量采用一致的对齐方式。表头、首列和筛选区从同一条线开始，相关信息之间的间距小于区块间距。
- **颜色与字体**　工作区底色与面板形成层次，细边框分隔记录。品牌色标识主操作、当前导航和焦点。成功、待处理与失败各有颜色，也用文字说明。五种纯色主题和四种图片主题共享布局。星河极光使用深色表面和浅色文字。界面字体随员工的外观选择变化，文档原件保持自身排版。
- **交互**　按钮使用业务动词。鼠标悬停和键盘焦点都能定位当前行。详情弹窗保留原列表上下文；关闭后可继续查看原来的记录。已读、审批结果或保存成功等状态，以业务确认结果为准。
- **窄屏与密度**　按内容区宽度换行或排列为单列。字段名和控件成组换行，操作仍可触达。宽表、树和已放大的文档在自己的区域内滚动，正常阅读页面无需左右拖动。

## 在代码里复用

| 层次 | 实现位置 | 使用方式 |
| --- | --- | --- |
| 主题与字体 | `web/src/design-tokens.css` | 选择已有语义变量，例如正文 `--ink`、辅助信息 `--text-secondary`、面板 `--surface`、主操作 `--brand` 和警示 `--danger`。可切换主题的界面元素从变量取色。 |
| 主平台 | `web/src/platform/theme.css`、`appearance.css`、`flowDialog.css` | 列表复用已有筛选、表格、页脚和空状态；业务页只定义专属布局，表单和弹窗优先延用现有类与组件。 |
| 独立档案工作台 | `web/src/style.css` | 将同一套变量映射给 Element Plus，表单、台账、操作抽屉和审批等路由自然继承。 |
| 阅读与打印 | `DocumentReader.vue`、`OfficeEditor.vue`、`PrintView.vue` | 屏幕工具栏使用平台主题。打印介质只输出已获批的文档页面；第三方 Office 文档区域使用其编辑器自身的呈现。 |

设计评审可用一条真实工作路径核对，例如查到一条公告、读正文并确认，然后回到列表。桌面和窄屏均需查看键盘焦点、空列表及错误提示，切换浅色和深色时也要检查按钮文字与文档原件。主题与字体的选项见[外观设置](frontend/appearance.md)。

留白、文字层级和员工信息的组织参考了 [Dribbble · StaffO](https://dribbble.com/shots/27654603-StaffO-Employee-Management-Dashboard-UI-Design)。表格操作、可读状态和一致的导航参考了 [Dribbble · HR Management Dashboard](https://dribbble.com/shots/26684545-HR-Management-Dashboard)。
