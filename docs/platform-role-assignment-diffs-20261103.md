# 人员角色按实际差异保存

后续规则更新：用户随后要求普通角色管理移除“批准依据、调整原因”两项要求，平台、公盘、档案均适用。下文保留首次差异修复时的验证记录；当前规则以 `platform-permission-validation-review-20261103.md` 为准。

2026-11-03，修复已有部门档案员只修改公盘角色时，被误要求走专用交接流程的问题。

原实现将表单中所有模块的任职结束后重建，并在目标已有档案员时直接要求交接。现在以角色及部门范围比较前后差异，仅结束被移除的任职、建立新增任职。未变化的任职编号、任期、批准依据和流程引用均保留，模块审计仅记录实际变化的模块。

用户本轮确认：仅调整公盘角色时，批准依据和调整原因均为选填，可省略、留空或正常填写；长度和类型仍按原字段限制。平台或档案模块实际变化时，两项继续执行原有必填规则。本人再验证、授权版本、单一公盘角色、授予能力范围和最后管理员检查继续执行。

完全未改变角色时，不更新账号版本、不重建任职，也不让员工的现有会话失效。实际角色变化仍立即撤销旧会话。只有真正撤销或更换部门档案员身份时，才要求专用交接；保留该任职而新增其他档案角色不会重建档案员。

13项真实IAM集成测试及40项前端测试通过，类型检查及平台构建通过。独立测试库55448中，经页面完成“已有部门档案员、两项留空、仅新增公盘职员角色”的保存，并重开核对；数据库快照确认其他模块任职逐字段一致。测试及截图保存在项目相邻 `tmp/role_assignment_diff_20261103/`，日常预览不注入合成人员或变更用户实际角色。
