# 公盘预览故障与服务可用性修复

2026-10-31，公盘文件上传检测恢复后，Office阅读仍失败。实际原件已经发布；页面把预览错误统一写成“尚未发布”，又保留旧上传成功提示，导致相互矛盾。

## 已确认原因与影响

- 旧联调脚本给服务身份设置一天有效期。日常预览迁移脚本直接复制了有效期，未按长期使用安排维护期限。公盘检测与Office身份在当日14:03到期，档案和人员台账检测身份也在当日到期。
- Office容器、WSL驻留进程和回调桥没有纳入日常预览的Windows后台任务。它们退出后，主网页仍然可以访问，不能据此认为阅读服务正常。
- 预览任务吞掉具体业务错误；检测任务领取失败后静默等待，没有指出服务身份失效。

## 修复

1. 备份后续期已配置的过期服务身份至2027-10-31，保留原部门、模块、动作、凭据和文件状态，记录续期审计。四类身份目前都有明确有效期，未设置永久授权或自动恢复停用身份。
2. 新增Windows任务`BioLink-IMS-UserPreview-Office-18457`，托管既有WSL、固定Office容器及日常回调桥；登录自动启动，健康检查失败退出后按一分钟间隔重启。应用异常退出也返回失败码供任务计划程序恢复。
3. 管理员各页面显示关键服务异常提醒，“运维与保护”显示完整有效期和Office连接检查结果。身份有效期实时查询，提前30天提示；Office每分钟核对服务版本。未配置、已停用、授权范围不完整、已过期和连接故障分别显示。
4. 统一服务身份授权边界，仍核验模块、部门、动作和状态。过期不能冒充用户撤权或文件损坏；阅读任务保留业务错误码。检测领取故障保留待处理任务，30秒后再试，同时将原因反馈页面。
5. 阅读错误明确说明文件已发布，无需重传；开始新操作时清除旧成功提示。后台检测失败不会被当作病毒检测通过。

## 维护

管理员看到30天到期提醒后，在确认服务仍需启用、范围正确后安排续期。当前本机维护入口为`scripts/platform/renew-user-preview-service.ps1`，必须明确服务、截止时刻、原因；先备份，事务记录审计，不修改权限范围、不恢复停用身份、不自动运行。例如：

```powershell
# 日期应替换为本次维护批准的未来一年内时刻。
./scripts/platform/renew-user-preview-service.ps1 -Service Office -ValidUntil '2027-10-30T18:00:00+08:00' -Reason '年度维护确认原Office服务与授权范围继续使用'
```

可选服务为`DriveScanner`、`ArchiveScanner`、`PlatformScanner`、`Office`。不要将测试夹具的一天有效期直接带入长期运行环境。今后更换环境或发布文件处理功能，验收需同时检查服务有效期、Office实际连接、上传检测、预览正文与翻页，不能只验首页HTTP 200。
