# 会议未完成情况导出

## 入口和范围

- 会议列表：“导出我发起会议的未完成汇总”。汇总当前账号发起的全部会议，不受当前列表筛选和分页影响。
- 本人发起的会议详情：“会议Excel”区域的“导出本场未完成情况”。
- 仅发起人本人可以导出本场数据。受邀人员、其他发起人、总经理的会议查看权、平台IT身份都不会扩大导出范围；请求他人会议返回不可见。
- 所有阶段均可读取当前状态，不必等会议办结。取消的会议、已移出的邀请不再追责。已发布的会后事项按实际责任人统计，也支持不是受邀人的责任人。

## 完成判定

| 环节 | 未完成口径 | 下一步处理人 |
| --- | --- | --- |
| 参会回复 | 当前邀请仍为未回复；不能因此认定其他材料也没提交 | 受邀人 |
| 会前填写 | 本场勾选、本人须填的材料缺少有效提交记录；上周工作内容、本周计划、协调事宜各自判断 | 填报人 |
| 会前资料确认 | 本人确有他人共享材料可读，但没有确认当前共享版本；材料变化会使旧确认失效 | 阅读人 |
| 会后待办与反馈 | 纪要已发布且开启跟踪后，实际分派事项为未反馈或退回补充 | 责任人 |
| 反馈确认 | 已提交反馈，尚待发起人确认 | 会议发起人 |

未开启的项目、尚未发布纪要的待办草稿、没有可读共享材料的阅读确认均不统计。网页填报和Excel导入共用同一材料表；合法提交的文本内容（包括无新增工作的说明）按已提交处理，空白不冒充提交。历史合并填报会议沿用原版材料提交记录，不凭空增加本周计划要求。

会前填写、回复及阅读以实际开始时间为已截止时间；尚未开始时使用预约开始时间。会后反馈使用事项原截止时间。未到截止时间可导出，标明待完成（未到期）；超期标明已逾期。发起人的确认环节没有独立期限，保留原任务截止时间供参考，并标明“不适用（未设置确认期限）”，不会把已反馈员工误算成未反馈。

## 表格

格式为xlsx，每人每个未完成项目一行，列为会议名称、会议时间、部门、姓名、工号、环节、具体事项、截止时间、当前状态、逾期情况、下一步处理人、处理人工号、导出时间。时间均为北京时间。

第一行说明范围、生成时间和数量；第二行为表头，冻结前两行并启用筛选。工号和事项均为文本单元格，前导零不丢失，以等号开头的事项不会执行公式。没有未完成事项时仍返回带表头且明确标注0项的工作簿。

导出使用一个数据库只读一致性快照，不修改会议、材料、反馈、审批或待办状态。不需要数据库迁移。

## 接口和验证

- `GET /api/v1/meetings/incomplete-export`：本人全部会议。
- `GET /api/v1/meetings/{id}/incomplete-export`：本人指定会议。

接口沿用会话、请求编号及HTTP审计；返回Excel媒体类型和禁止缓存头。失败通过统一错误响应返回。页面先检查错误、媒体类型及空文件，防止把错误JSON保存为Excel。

隔离回归覆盖当前/汇总范围、越权、不同填报来源、部分提交、阅读版本变化、未触发项目、反馈提交/退回/确认、取消/移出及空结果；保留原有会议填报模板与汇总导出功能。
