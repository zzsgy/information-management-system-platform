# IT配置、保护与独立维护操作说明

适用本次平台版本。完整升级应用并执行数据库迁移至76（V75为服务身份，V76为部署配置与执行器心跳）。如部署固定Flyway目标版本，先备份再调整，不能只替换网页。

## 一、网页在哪里配置

平台IT管理员登录 → 管理中心 → 运维与保护 → **部署运行配置**。六个页签分别是文件检测、原件存储、阅读与导出、Office连接、存储保护、备份与维护。原有四类服务的部门范围、有效期、启停状态在下方“文件处理服务配置”维护。

每组填写修改原因、点击保存，输入本人登录密码再验证。后端核验IT身份、权限、当前版本和操作号，配置与审计同事务提交，成功提交后生效。普通员工不能读取部署路径、下载安装包或修改配置。输入的是部署电脑路径，不是浏览器所在电脑路径。密码和密钥正文不会返回网页；密钥和恢复账号使用部署机私有文件。

保存不等于检查通过。点击“检查运行环境”实测无害文件检测、PDF解析、双目录、目录权限、导出、Office版本、备份与执行器心跳，失败显示具体原因、错误码与请求编号。处理后重新检查。

## 二、各组填写什么

| 页签 | 填写与处理 |
| --- | --- |
| 文件检测 | 部署机ClamAV的clamscan.exe、官方病毒库目录、私有临时目录、超时；开启后台文件处理器。保存时计算程序SHA256，后续仍核验官方库及7天有效性。程序更新后重新保存固定摘要。按ClamAV安装方式启用freshclam更新病毒库。 |
| 原件存储 | 两个互不嵌套的绝对目录。已有对象时不能在线切换持久路径；需停机复制、核验并调整配置，不能把修改文本当作文件迁移。 |
| 阅读与导出 | Java可执行文件、pdf-page-worker JAR、阅读临时目录、回执目录、导出主/次/临时目录。处理JAR由本项目processing/pdf-renderer构建提供。 |
| Office连接 | 可选，未部署可停用。启用时填写浏览器/服务器/平台回调HTTPS来源、版本、两份不同的私有签名密钥文件、临时目录。配置不会安装Office服务器。 |
| 存储保护 | 单台部署选“单机双副本与独立完整备份”，设置最长备份间隔（默认24小时）。必须完成有效完整备份后才允许业务文件写入。若用外部主备，填写真实代理的证据文件、密钥文件、节点编号；需另行部署真实代理，本系统不签发虚假正常证据。 |
| 备份与维护 | 启用维护，填写检查临时目录、PostgreSQL bin、独立磁盘备份目录、恢复应用端口、恢复账号私有JSON、Node程序、服务启动私有JSON、Windows应用服务名称。下载独立执行器安装包，在部署机安装一次。 |

所有持久目录、临时目录、账本、邮箱和备份输出不得互相包含。备份须在其他卷，另一个D盘文件夹不能算独立备份；不同卷也不证明不同物理盘，部署人应选择真实独立磁盘或独立存储。双目录副本不等于独立备份，单机模式不等于双机高可用。

## 三、部署电脑首次安装独立执行器

这是服务器首次安装工作。网页不应静默取得Windows管理员权限，也不能替你安装PostgreSQL、ClamAV或Office。下面命令**只在部署电脑执行**；代码开发电脑无需运行。

1. 将应用部署成Windows服务，记下实际服务名称（不是显示名称）。服务启动仍读取原来的私有启动JSON；数据库连接、HTTPS证书、服务账号是首次启动的必要条件。
2. 安装Node及与数据库版本一致的PostgreSQL客户端工具。IT页面填入实际路径、服务名，保存。
3. 保管服务私有启动JSON，必须含现有IMS_PLATFORM_DB_URL/USER/PASSWORD、应用端口、账本和邮箱等已使用参数。不要把它上传Git或放在网站静态目录。执行账号须与应用服务账号具有一致的文件读写能力、数据库备份权限和该服务停启权限。
4. 点击“备份与维护 → 下载独立执行器安装包与说明”，解压到部署电脑固定目录，例如 `C:\IMS-Tools\operations-agent`。
5. 用管理员PowerShell运行以下命令，**替换三个路径**。输入服务账号凭据，由Windows任务计划程序保管。脚本只安装计划任务，不立即备份。

```powershell
& 'C:\IMS-Tools\operations-agent\Install-OperationsAgent.ps1' `
  -Node 'C:\Program Files\nodejs\node.exe' `
  -Bootstrap 'C:\IMS-Private\platform.private.json' `
  -PostgresBin 'C:\Program Files\PostgreSQL\17\bin'
```

默认任务名 `IMS-Operations-Agent`，每分钟检查一次，不并发运行。只有数据库存在等待窗口的备份/恢复任务时才停止指定应用服务；原件、其他Java进程和数据库服务不会被删除或停止。finally恢复应用服务。失败的输出保留，不覆盖旧备份。服务意外本来已停止时，执行器不擅自启动；请先核对原因。

回到网页检查心跳。计划任务账号需要访问独立备份盘；若为网络盘，使用服务账号可访问的UNC路径，不依赖登录会话的映射盘。任务故障查看Windows任务历史及独立维护日志，网页保留任务错误码与请求号。

## 四、首次备份与日常计划

1. 首次配置单机保护可能显示LOCAL_BACKUP_REQUIRED，这是要求先备份，不会阻止IT修复配置或申请备份。
2. “检查与维护申请”选择独立备份，填写原因、再验证后提交。页面显示等待停机窗口。
3. 独立执行器读取网页保存的参数，核验当前账号授权；停止应用 → 确认应用端口关闭 → 数据库一致性快照与完整导出 → 复制所有已配置持久目录并校验SHA256 → 保存清单 → 登记已验证备份 → 启动应用。
4. 只在实际验证完成后出现备份记录。数据库导出、原件/历史源、双副本、账本、回执、导出、邮件与审计归档目录都纳入；启动JSON、HTTPS证书和已配置Office/保护密钥另外保存在私有配置子目录。该目录包含秘密，不能向普通员工开放或提交Git。
5. 在独立备份页签设置每日计划（上海时区）、保留天数。到点排队，由上述执行器执行。保留期不自动删除旧备份。

备份停机会短时无法访问网页。按分钟刷新即可；离线执行结果保存在库中，应用启动后页面可查询。切勿手工把失败任务改成成功。

## 五、隔离恢复账号与演练

先在部署电脑准备另一个**本机PostgreSQL实例**（端口必须不同于源库），维护库postgres，配好能创建新库的维护账号和恢复应用账号。下面JSON仅为模板，替换端口、账号、密码，限制为服务账号可读：

```json
{
 "IMS_RESTORE_DB_URL": "jdbc:postgresql://127.0.0.1:55486/postgres",
 "IMS_RESTORE_DB_USER": "restore_owner",
 "IMS_RESTORE_DB_PASSWORD": "替换为恢复实例维护账号密码",
 "IMS_RESTORE_APP_USER": "restore_app",
 "IMS_RESTORE_APP_PASSWORD": "替换为恢复应用账号密码"
}
```

在“备份与维护”填写该私有JSON文件路径。**隔离恢复应用端口**是演练站点将来使用的端口，例如18599，不是上述55486数据库端口。恢复输出在独立备份根目录下的全新任务目录，新数据库固定命名ims_platform_test_restore_加任务号。既有库、源库、既有文件和备份都不覆盖。

在页面选择已验证备份，申请隔离恢复。执行器停源应用、验证清单、恢复新库与新目录、逐表与逐文件核对，复制当前安全账本，完成后启动源应用。结果RESTORED_VERIFIED_NOT_OPENED表示技术校验完成，恢复站点尚未开放；仍需业务复核。

恢复配置包含IMS_PLATFORM_ISOLATED_RESTORE=true，启动时禁止数据库里的原部署参数盖回原路径或启用原工作器。不要删掉该标记直接开放业务。正式切换需重新核对所有路径、服务身份、备份与保护，完成业务复核后单独安排。

## 六、接口与故障处置

- `GET /api/v1/admin/operations/service-configurations/deployment`：IT读取分组参数。
- `PUT .../deployment/{id}`：DEPLOYMENT_SETTINGS/CONFIGURE_DEPLOYMENT再验证、版本、幂等和审计。
- `GET .../deployment-agent.zip`：IT下载公开脚本和模板，不含部署秘密。
- `POST .../check`：实测运行环境，返回请求编号；不修改业务文件或员工权限。

MAINTENANCE_AGENT_OFFLINE检查计划任务、执行账号和服务名；MAINTENANCE_TOOL_MISSING检查PostgreSQL bin；BACKUP_VOLUME_NOT_INDEPENDENT换独立备份盘；LOCAL_BACKUP_REQUIRED先做完整备份；LOCAL_BACKUP_UNAVAILABLE检查备份盘及目录；SCANNER错误检查程序、官方病毒库、摘要和权限。详细异常写入服务器日志，页面不暴露数据库密码和密钥。
