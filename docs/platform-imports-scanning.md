# 批量导入与扫描批次管理

本批接续目录维护、审批凭据和人员交接，依据需求 V0.5、接口及数据库设计 V1.1 实施。后端位于 `backend/`，电脑端页面位于 `web/src/platform/Imports.vue`、`Scanning.vue`。旧系统、原预览及其数据库不切换。本批验收使用全新隔离数据库与附件目录。

## 业务入口与办理顺序

### 批量导入

1. 档案盒登记使用用户提供的十八列中文通用台账，所有部门共用同一模板，保留第 2、3 行合并表头，从第 4 行填写。文件登记选择“文件登记（关联档案盒）”，继续使用带盒件关联的字段模板。员工、部门及文件关联模板仍使用 `IMS-IMPORT-1` 的前两行标识。
2. 档案登记不再手动选择下载模板的部门：每行按表内部门名称（文件关联模板按部门编码）定位，服务端仍按当前实际维护权限逐部门核验。员工、部门导入继续明确选择批准范围。上传 `.xlsx` 经分片、双副本校验及服务器真实文件检测后才能预检。拒绝外部链接、宏、重复行列及任意公式；仅中文台账允许原表到期日期列的同一行 `M行号+365*N行号`，由服务端重新计算，不执行 Excel 表达式或采用缓存结果。
3. 预检展示原表行号和字段错误，不创建业务对象。有错误时修正源表并新建批次，保留旧批次结果。上限为 1,000 条数据行；浏览器文件上限 50 MiB，解压后各文件及总量另受限制。
4. 确认时再次验证本人密码、批次版本、固定预检摘要及当前员工、部门、模板和目录规则。全部新增在同一数据库事务中完成；任何一行失败整批回滚，重复提交不重复创建。
5. 员工临时凭据进入既有受控投递渠道，列表和结果不返回密码。部门支持本批先子后父，按依赖次序创建，循环层级拒绝。两类台账均不用于修改已有账号或部门。
6. 档案确认只建立盒、件和候选修订，结果为“待质量检查与复核”。不会自动发布、开放阅读或批准下载。后续仍需真实 PDF、人工质量检查与独立归档审批。
7. 未发布档案可整批撤回；本人尚未完成的归档流程通过已有流程撤回机制一并结束。已发布、有批次外成员引用、已进入扫描作业或其他人的在审流程时整体拒绝。历史、原编号映射与审计记录保留，不物理删除。

档案每行填写 `BOX` 或 `RECORD`，`rowKey` 为本批唯一行标识；文件只能填写本批 `boxKey` 或已有 `boxNo` 之一。`originalNumber` 保留原编号，系统号仍按既定规则生成。工号、编号、ISO 日期应使用文本单元格；关键词使用分号，扩展字段使用对应目录模板的 JSON。纯纸质和混合载体均须填写原件位置。可选模板标识在页面“填写说明与目录模板”中查询。

### 2026-11-03 档案盒通用台账

以上英文内部字段仅用于文件关联模板。档案盒模板与用户的《档案台账清单-空.xlsx》列顺序一致：档案编号、档案名称、文件类型、所属部门、档案负责人、存放柜号、存放列号、存放层号、清单、保存类型、保存份数、保密级别、存档日期、有效期限 / 年、到期日期、档案状态、备注、最后更新时间。存放位置保留合并标题；下载模板为空白，不附带真实档案和人员。

- 每行登记一个盒；部门、负责人直接填写系统中的中文名称。部门须唯一且在当前维护范围内；负责人须为同部门的有效人员，同部门同名时拒绝模糊匹配，不自行选择第一个人。
- 支持原表的 Excel 数字日期、中文或 ISO 文本日期，以及原表到期日期公式。允许保留原件第二张“部门及档案负责人”参考表，其内容不导入账号、不分配角色、不作为人员存在性的证明。其他多表组合仍拒绝。
- 文件类型、三段位置、清单、保存类型、保存份数及来源日期状态全部保留。份数不计入尚未登记的盒内文件数。原档案编号可空，有值时保留旧号映射；系统盒号继续按原有规则分配，编号月份取存档日期所在月份。
- 原台账“到期日期、档案状态、最后更新时间”作为来源字段保留。系统草稿、归档复核状态、操作时间和按日历年计算的保管截止日期仍由平台产生；不会把台账中的“正常”直接当成已复核发布。原公式按 365 天每年计算的日期也不会悄悄覆盖。
- 有效期限沿用当前 5、10、30 年或永久规则；保存类型支持纸质原件、电子文件、混合，保密级别支持一般、重要、核心。缺失及不支持的值进入预检错误，不默认为低密级。
- 单条盒及文件登记默认选择“通用档案（所有部门）”及共用台账模板；历史六类模板、既有目录和修订保留。新增迁移 `V45__common_archive_ledger_templates.sql` 只扩展通用类别及两份不可变模板。

### 模板下载与保存反馈

2026-11-03 补充：用户确认原下载实际已唤起保存窗口，但该窗口在另一浏览器窗口后台，被取消后页面没有提示。HTTP 200 不能作为已经保存的验收证据。

模板入口改为显式保存操作。支持文件保存选择器的浏览器，在当前点击中先聚焦本窗口并立即选择保存位置，再请求模板并写入选中的文件。页面区分等待选择、正在保存、实际写入完成、取消及接口错误；文件句柄不持久保存。取消只提示可重试，不显示成功。无法使用保存选择器的浏览器继续走普通下载，并保留当前弹窗内的保存链接。

模板接口和权限不变，响应仍校验为非空 XLSX。验收只能在用户实际操作的浏览器窗口触发一次保存，避免另开后台窗口连续唤起原生保存框。保存文件内容仍须核对表头和合并范围。

批次列表仅展示本人仍可维护的范围，授权过滤先于分页和统计；人员调岗或撤权后不能通过旧批次继续确认或读取详情。

### 扫描作业

1. IT 在“扫描作业 → 设备与接收范围”登记设备、软件版本、受控暂存位置及批准输出渠道，绑定唯一部门与专用服务身份。密钥只写入服务器私有配置目录，不通过网页返回。IT 的设备配置权限不会同时授予档案内容权限。
2. 档案员选择本部门启用设备，登记原件清单、页数、状态、附件关系和特殊作业标记。每批最多 50 件，当前接收未发布的混合载体档案；已有扫描批次或已有候选 PDF 的文件不得另建批次绕过原流程。
3. 登记取出、暂存保管及归还。交出人、接收人分别填写，核对数量必须与清单一致。特殊作业由不同于批次登记人的档案超级管理员批准。需要复原、破损处理或异常处置时保留真实办理记录。
4. 专用代理在 HTTPS 上使用服务签名，按固定批次与文件清单上传。分片及任务都有稳定标识，断网重试沿用日志；服务端执行真实病毒检测、内容类型检查、双副本摘要核验和独立 PDF 页数解析。代理自报“检测通过”无效。
5. 接收回执绑定设备、批次、文件、上传会话、轮次、哈希和页数。同一回执或重复完成只产生一份当前候选。收到文件后状态为待质检，不自动归档。
6. 档案员通过个人水印逐页检查，核对正反面、折页、附件、印章、裁边、页序、重复页及档号对应。服务器实测、代理实报、清单预期和人工核对页数必须一致才能通过。返工保留旧 PDF 与记录，增加轮次并使旧阅读会话和旧上传绑定失效。
7. 需要更正页数或对应关系时，使用原批次“纠正对应”。已接收 PDF 不能移挂到另一档案。批次总页数随明确更正更新。暂停后必须先登记处置，再由另一名有权人员批准恢复。
8. 暂存清理要先获得独立批准，再登记实际完成；程序不会自动删除扫描源文件。关闭要求全部质检通过且原件已经归还。实体归还与电子质量状态分开记录。

## 接口和并发边界

人员接口位于 `/api/v1`，沿用 Cookie、CSRF、`X-Operation-Id`、对象版本和对象/动作绑定的再验证令牌。

| 接口 | 用途 |
| --- | --- |
| `GET /imports/templates/{type}`、`/imports/options/{type}` | 当前模板与授权部门选择 |
| `POST /imports/batches` | 固定已检测原件和部门范围，预检 |
| `GET /imports/batches`、`/{id}`、`/{id}/rows` | 本人范围内分页批次与逐行结果 |
| `POST /imports/batches/{id}/confirm`、`/withdraw` | 摘要、版本及当前授权绑定的整批确认/撤回 |
| `GET /admin/archive/scan-options`、`/scan-devices` | 最小设备配置选项和设备列表 |
| `POST /admin/archive/scan-devices`、`PATCH /{id}` | IT 登记和启停接收 |
| `GET/POST /archive/scan-batches`、`GET /{id}` | 部门范围内批次及清单 |
| `POST /archive/scan-batches/{id}/events` | 原件交接、特殊批准、暂停处置、恢复和关闭 |
| `PATCH /archive/scan-items/{id}` | 纠正页数/对应关系，增加接收轮次 |
| `POST /archive/scan-items/{id}/quality-reviews` | 人工通过或返工 |

设备接口位于 `/internal/archive`，只允许 HTTPS，拒绝浏览器 Origin、查询参数及超大正文。JSON 上限 64 KiB，分片固定 8 MiB，单 PDF 上限 1 GiB。

| 接口 | 用途 |
| --- | --- |
| `POST /scan-upload-sessions`、`GET /{id}` | 创建和恢复固定文件会话 |
| `PUT /scan-upload-sessions/{id}/parts/{number}` | 摘要、大小、范围与轮次均验证的分片 |
| `POST /scan-upload-sessions/{id}/complete` | 创建检测任务；可重试的失败最多尝试 5 次 |
| `POST /scan-receipts` | 检测通过后绑定候选及固定回执 |
| `GET /scan-batches/{id}` | 仅状态、标识和页数的最小设备回执 |

签名头为 `X-Service-Id`、`X-Service-Time`（Unix 秒）、`X-Service-Nonce`（新 UUID）、`X-Content-Sha256` 和 `X-Service-Signature`。签名为 HMAC-SHA256 十六进制，原文为 HTTP 方法、绝对路径、时刻、随机数、正文摘要，以换行相连。时间容差 300 秒，随机数独立事务消费；业务重试必须使用新随机数但保留原操作号、事件号与回执键。每阶段重新检查设备启用状态、服务有效期、部门范围、批次状态、当前轮次及存储保护状态。

数据库使用批次/对象行锁、唯一约束和不可变快照，导入遵循已有全局身份变更锁。扫描耗时文件操作在事务外执行，完成事务再次检查冻结输入和租约。任务租约 20 分钟，失效尝试保留，多个服务节点不能重复接受同一结果。列表按索引分页，上传流式摘要，单轮工作器最多取 2 个任务。原件、候选、质检、归档审批分别保留；没有以接收成功代替审批的快捷通道。

本轮回归同时发现既有通知领取可能先扫描全部历史通知，再执行复杂授权函数，导致领取一条消息超时。领取已改为先通过 `SKIP LOCKED` 锁定单条到期候选，再按通知主键检查当前权限；失效项取消并保留历史，单次检查数量有界。原租约的未知投递结果仍记录为 `UNKNOWN`，实际投递前继续复核，业务审批不会因通知重试重复执行。

## 部署配置及代理

新增迁移 `V25__imports_and_scan_intake.sql`、`V26__intake_snapshot_guards.sql`；不改写既有迁移。新增表与字段带中文数据库注释。

| 环境变量 | 用途及默认值 |
| --- | --- |
| `IMS_PLATFORM_SCANNER_PLATFORM_SERVICE_ID` | 独立平台台账检测身份；空值时该类检测不能成功 |
| `IMS_PLATFORM_SCANNER_ARCHIVE_SERVICE_ID` | 复用独立档案检测身份，必须覆盖当前部门 |
| `IMS_PLATFORM_SCAN_KEY_DIRECTORY` | 私有扫描密钥目录；默认空，设备接收关闭 |
| `IMS_PLATFORM_SCAN_WORKER_ENABLED` | 扫描检测工作器开关，默认 true |
| `IMS_PLATFORM_SCAN_WORKER_DELAY_MS` | 轮询间隔毫秒，默认 5000 |

专用 `SCAN_INTAKE` 身份默认有效期一年，仅允许指定部门的 `SCAN_UPLOAD/SCAN_RECEIPT`；正式部署须纳入密钥保管、到期及更换制度。当前页面提供启停与有效期查看，不自动续期。检测身份继续使用 `FILE_CHECK`，不能把接收身份同时当作检测结论来源。

参考代理使用现有 Node 22+，无新增第三方包：

```powershell
node scripts/platform/scan-agent.cjs <私有配置.json> <受控清单.json>
```

配置字段：`baseUrl`（无凭据和查询串的 HTTPS 根地址）、`serviceId`、`keyFile`（服务器私有密钥的受控交付副本）、`caFile`（可选企业 CA）、`stagingRoot`（批准扫描暂存目录）、`journalRoot`（受控重试记录目录）。所有文件目录均用绝对路径，代理必须有最小必要的文件权限；配置和日志不放入代码仓库。

清单字段：`manifestId`（本轮固定 UUID）、`deviceId`、`batchId`、`items`。每项为 `itemId`、`source`（暂存目录内相对 PDF 路径）、`receivedPages`。返工新建清单标识，保留旧日志。同一清单不能改写原文件或来源路径；代理校验实际路径，拒绝越界和指向其它位置的链接。

重试记录先落盘再请求，写入使用临时文件、fsync 和原子重命名。同一清单有独占锁；如代理崩溃遗留 `.lock`，运维须核查日志及对应进程确已退出后处理该锁，再用同一清单重试。程序不按猜测的超时时间抢占。未完成、检测失败、证书或连接异常均保留源文件，不切换临时输出渠道，不绕过证书校验。

## 验收范围

本机验收覆盖真实 PostgreSQL、双副本文件、原生检测进程、PDF 子进程、HTTPS 签名代理和 Edge 电脑端操作，详见本批验证记录。隔离检测库使用无害合成签名验证进程及拒绝逻辑，保护事实为测试签名，不代表正式病毒库、独立备份或真实扫描设备已验收。

真实扫描仪驱动/软件版本、扫描质量、现场受控暂存、非授权输出阻断、跨主机网络和生产 CA、私钥交付以及正式独立备份仍须在部署现场核验。当前参考代理可用于已扫描 PDF 的受控接收；不声称已远程控制真实扫描仪。邮件和生产账号配置沿用既有部署条件。
