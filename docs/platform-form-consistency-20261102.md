# 全平台表单样式整理与验收

日期：2026-11-02。按用户提供的“登记档案盒”截图，检查新平台所有页面的输入框、下拉框、文本域、表单网格及弹窗。仅处理电脑端；历史Python界面不在当前网页系统范围内。

## 原因与修复

原`theme.css`把普通字段强制设置为“文字和控件同行”，并把控件定位在第二个网格列。不同长度的标签导致输入起点不同，局部组件本来的单列表单也被覆盖。档案登记网格的纵向间距为0，控件上下紧贴。公盘、导入、扫描等页面另有局部控件规则覆盖公共圆角、边框和内边距，后续容易再次出现差异。

- 普通字段统一为标签在上、控件在下，同列输入起点一致；文本输入、日期、月份、数值和下拉框采用40px标准高度、7px圆角及共享焦点样式。文件选择、复选框、单选框和专用阅读控件保留其用途对应的结构，不用文本框布局强制改排。
- 公共`form-grid`承载两列字段，行距20px、列距24px，网格子字段不再叠加外边距。档案登记、借阅期限、打印申请、目录维护、模板定义、动态字段、实物借还及扫描表单接入；公告与网站网格使用相同间距。
- 档案登记弹窗宽度为800px并受电脑窗口约束；弹窗内边距28px。目录维护和模板弹窗也接入共享边框、圆角、背景遮罩与最大高度。长表单在弹窗内纵向滚动。
- 动态目录字段说明移到控件下方，避免某个字段有说明时把同一行的输入框挤到不同高度；字段值更新及停用行为保持原实现。
- 清除公盘配置、文件详情、回收站、Office状态、扫描和批量导入等页面重复的普通控件装饰；保留业务专有分栏、表格和权限选项。凭据提交、复核表单同步增加行间距。

主要源文件：`web/src/platform/theme.css`、`portal.css`及相关业务组件。没有修改业务API、角色规则、密码规则、数据迁移或后端程序。
