# 员工离职与历史归档

管理中心的「员工离职」和「员工转岗」是独立入口。平台 IT 人员管理员可以按姓名或工号查找在用及临时停用的具名员工。核对身份、撤权影响和待接手事项后，填事由并使用管理员本人的密码确认。共享 IT 账号和当前操作者不能从此入口办理。

## 数据库设计

| 对象 | 存储内容 |
| --- | --- |
| `iam.user_account` | 保留账号 UUID 及历史关联。新增 `DEPARTED` 状态，登录和原有账号启用入口拒绝使用。 |
| `iam.employee_departure` | 每人一份主档。保存离职时的姓名、工号、部门、之前的账号状态、办理人、原因、时间、请求号和影响数量。 |
| `iam.employee_departure_record` | 每条历史快照独立成行，按主档、来源、原记录编号唯一归档，可按类别及时间分页。记录来源覆盖操作审计、页面操作、任职和授权、转岗、审批、实物、公盘版本、档案登记、会议、待办、反馈和公告。 |

`V87__employee_departure.sql` 创建归档结构和批量快照函数。主档和记录禁止覆盖或删除。快照保留业务编号、状态、事件时间和必要的追踪字段，业务正文和附件由原模块保管，仍使用原权限。离职工作台可查归档快照，登录令牌、密码及验证码禁止进入快照。

## 撤权与后续责任

一次办理事务完成数据库归档、结束角色与审批职责、撤销个人权限和公盘及档案授权、使阅读凭据失效、收回待发密码或找回凭据，并将账号标为已离职。会话及旧授权代次通过现有身份账本失效，公盘协作通过现有账号变更保护接续。未完成且会产生新授权的本人申请沿用现有终止逻辑。

已经发生的审批决定、文档版本、反馈和其它业务事项保留原经办人。尚未归还的实物仍登记在原借用人名下，待接手的审批按原流程改派。办理前及归档页均可看到这些数量。
