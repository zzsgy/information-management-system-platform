## 真实客户端与服务联合验证

在本机新建数据库运行打包后的Java服务，以实际`ApiClient`执行`client/tests/java_live_smoke.py`，退出0，输出`JAVA_CLIENT_SMOKE_OK steps=11`。覆盖：

1. 登录并读取实际权限及业务目录。
2. 草稿新增、编辑、归档，直接修改生命周期状态被拒绝。
3. 上传、预览、下载，字节摘要一致。
4. 纸质借阅通过通用待办审批，再办理借出与归还。
5. 销毁申请与批准清单绑定；替换为另一档案被拒绝，范围外档案保持不变。
6. 正确整单执行后再次执行被拒绝，已销毁档案的附件不可访问。
7. 退出后旧令牌失效。

完整脚本中的11个检查步骤以断言验收；上面按业务链合并说明，不表示完成所有页面的人工作业验收。

## 实际备份与恢复演练

对联合测试库调用整体备份接口，真实执行`pg_dump`及`pg_restore --list`，生成包含数据库、全部历史附件和校验清单的`.imsbackup.zip`，接口返回`verified=true`。源附件检查：1项正常、0项失败。

停止测试服务后，通过`scripts/java/restore.ps1`及独立`OfflineRestore.java`恢复到另一个**新空库与不存在的新附件目录**，命令退出0。恢复工具逐项核验数据库附件元数据与备份实体，保留原库及原附件，并撤销恢复出的旧会话。

独立SQL核对：恢复库保留2条档案、1条附件记录、4个成功迁移记录；恢复完成时未撤销会话数量为0。随后使用恢复库和新附件目录启动Java服务，验证健康状态、管理员登录、档案读取及附件完整性。已逻辑销毁的档案仍保留审计数据，不重新出现在普通列表中。

这证明本次小规模测试样例可以实际恢复，不表示任意规模、跨大版本或公司正式备份已验收。
